# Qwertycoin GUI v2.0.5

## Source and dependency

GUI product version: `2.0.5`. Exact merged Core source:
`f1db1c0df16b180c608d609a6e5966c701d1c292` (Core #230).
The embedded daemon product version is `2.0.5`; legacy hardware/ZMQ
compatibility remains `2.0.5.0`. Every package must record the final merged
GUI source and this Core pin in `BUILD-INFO.txt`.

This pin includes the EPoSE reversible mutation journal RAM optimization and
the canonical Qwertycoin version identifiers. The optimization removes
per-block full-state copies without pruning history or shortening the full
undo horizon; it is not a bound on total RSS. Replay, deep rollback and
exception/failure atomicity are verified by the Core suite.

GUI EPoSE RPC observation, explicit local producer flags, network-bound
keystore paths, remote-node observation-only behavior and updater contracts
are unchanged and must pass against this pin. Core source-only `MONERO_*`
aliases preserve downstream compilation; all components are rebuilt.
The QML version-identity acceptance test compares the generated packaged GUI
version resource with the linked Core product constants used by the settings
UI. It separately verifies the legacy source alias and four-component
compatibility version. The settings UI uses `QWERTYCOIN_VERSION_FULL`, not the
four-component `MONERO_VERSION_FULL` compatibility alias.
RandomX secures block production and chain selection; EPoSE rewards service.
No consensus/network/wallet format change is introduced by this GUI update.

## QMS1/Fast Messenger

This release includes the experimental native Messenger from GUI PR #63,
using the existing QMS1/Fast wire profile supported by the pinned Core and
Web Wallet. It adds conversations, invitation/contact management and grouped
Messenger transaction history, including exact carrier recovery after a
wallet restore. Ordinary payment rows and raw wallet/CSV history are preserved.

Messenger requires an unlocked full wallet with a non-empty session password.
Contacts must be verified using their complete fingerprint before sending or
displaying incoming plaintext. Identity, messages and signed recovery plans
remain in the encrypted wallet cache. Sending uses prepare/review/commit;
an ambiguous broadcast retries the same remaining signed plan, not a rebuilt
transaction. Messages incur ordinary network transaction fees.

This is not QMS2: no forward secrecy, post-compromise recovery or post-quantum
protection is claimed. Transaction metadata remains public. See the
[Messenger security boundary and compatibility notes](../QMS1_FAST_MESSENGER.md).
Messenger navigation, verification/composer restrictions, UTF-8 limits and
carrier-history classification must pass the QML regression suite alongside
the version/EPoSE/updater gates.

## Release gates and limitations

Native targets are built sequentially: Linux x86_64, Windows x86_64, then
macOS Apple Silicon. Each uses one immutable merged GUI source and the same
Core pin, with development mode disabled and updater enabled. Required
GUI/QML/EPoSE/updater CI, package provenance, runtime/dependency smoke, Windows
installer data preservation and macOS copied-app smoke remain mandatory.
The existing assembly verifies all three successful candidates before
publishing five native packages plus `SHA256SUMS`.

This is a public-test client release, not an audited EPoSE activation claim.
The EPoSE audit/readiness gate remains `no-go` (0/13), not candidate-bound.
Linux and Windows artifacts are unsigned. macOS 15+ ARM64 is ad-hoc signed,
not Developer ID signed or notarized. Hardware-wallet support remains
unvalidated and fail-closed. These source notes document release requirements;
native candidates and public assets are verified separately by the assembly
and public-download gates.
